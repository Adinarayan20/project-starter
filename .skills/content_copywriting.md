# Antigravity Skill: Content & Copywriting
# Priority: HIGH | Impact: 9/10 | Rating: ⭐⭐⭐⭐½
# 🆕 NEW SKILL

## ACTIVATION
Load when: writing ANY copy for a public page — headlines, CTAs, feature descriptions, testimonials.
Copy is the product. Bad copy = users leave. Good copy = users convert.

---

## CORE RULE
> Every word on a public page is a conversion opportunity or a drop-off point.
> Write for one specific person, not "everyone." Vague copy speaks to no one.

---

## LANDING PAGE STRUCTURE (Proven Formula)

### SECTION 1: HERO (Above the Fold)
```
Required elements:
  ✅ Power Headline    — 8 words max. Benefit-first. Specific outcome.
  ✅ Sub-headline      — 1 sentence. Supporting claim. More detail on the headline.
  ✅ Primary CTA       — Action verb + specificity. What happens when they click?
  ✅ Secondary CTA     — Lower commitment option (e.g., "Watch Demo")
  ✅ Social proof bar  — Logo strip or "X,000 users" counter below CTA

Visible without any scrolling on mobile (dvh-based layout).

Example (good):
  Headline:   "Ship your backend API in 4 hours."
  Sub-head:   "Stop writing boilerplate. Focus on your product logic."
  Primary CTA: "Start Building Free →"
  Secondary:  "See a 2-minute demo"

Example (bad):
  Headline:   "The next-generation platform for modern teams"
  Sub-head:   "Empowering developers with seamless workflows and cutting-edge tools."
  CTA:        "Get Started"
```

### SECTION 2: PROBLEM AGITATION
```
Purpose: Make the user feel seen. Show you understand their pain.

Structure:
  ├── Name the exact frustration (be specific, not generic)
  ├── "You've probably experienced..." language
  ├── Describe the consequence of the problem
  └── Hint at the existence of a better way (don't reveal yet)

Example:
  "You've spent another Friday debugging a deploy that broke in production.
   Your team shipped the wrong version again. The on-call rotation is burning people out.
   There has to be a better way."
```

### SECTION 3: SOLUTION REVEAL
```
Structure:
  ├── How it works in 3 steps MAX (simple language, active verbs)
  ├── Demo / Screenshot / Video (show, don't just tell)
  └── "That's it." or similar closing line (signals simplicity)

Steps format:
  1. Connect your repo    — Takes 2 minutes
  2. Define your pipeline — No YAML required
  3. Deploy automatically — One button, every time
```

### SECTION 4: FEATURE BENEFITS
```
RULE: Lead with the BENEFIT. Follow with the feature.

Formula: "[Benefit], so you can [outcome]."

Wrong: "Advanced real-time collaboration features"
Right: "See every change as it happens — no more out-of-sync versions"

Wrong: "AI-powered code completion"
Right: "Ship 40% faster — AI writes the repetitive code so you don't"

Each feature needs:
  ├── Benefit headline (outcome, not technical description)
  ├── 2-3 sentence supporting explanation
  └── Visual: screenshot > illustration > icon
```

### SECTION 5: SOCIAL PROOF
```
Requirements:
  ✅ Named testimonials — full name + job title + company (no anonymous)
  ✅ Photo of real person (not avatar placeholder)
  ✅ Specific outcome in the quote: "Saved us 6 hours per week" not "Great tool!"
  ✅ Company logo strip (recognizable brands = trust transfer)
  ✅ Star rating + review count if applicable

Template for strong testimonial:
  "[Specific result they got] since using [Product].
   [What problem it solved for them specifically].
   [Name], [Title] at [Company]"

Example:
  "We cut our deploy time from 45 minutes to 8. That's 3 hours a week 
   we're spending on features instead of ops."
  — Sarah Chen, CTO at Veritas Labs
```

### SECTION 6: PRICING
```
Psychology principles:
  ├── 3 tiers: Anchoring makes middle tier feel "right"
  ├── Annual toggle: Default to annual (show % savings prominently)
  ├── "Most Popular" badge on middle tier
  ├── Feature list: Lead with what they GET, not technical specs
  ├── One clear recommended tier per user type

Pricing copy rules:
  ❌ "Cheap" or "Affordable"    → ✅ "Free to start" / "Saves you X per month"
  ❌ "Basic" as lowest tier     → ✅ Name tiers after outcomes or user types
  ❌ Long feature comparison list → ✅ Top 5 differentiating features per tier

CTA on each tier:
  Free/Starter: "Start Free" (no risk)
  Growth:       "Start 14-Day Trial" (low risk)
  Enterprise:   "Talk to Sales" or "Schedule a Call"
```

### SECTION 7: FAQ
```
Purpose: Answer the objections stopping conversion.

Identify objections by asking:
  "What would make someone NOT buy this right now?"

Common objections to address:
  ├── "Is it hard to set up?" → Show time to first value
  ├── "What if I need to cancel?" → No lock-in, cancel anytime
  ├── "Is my data secure?" → Link to security page
  ├── "Does it work with [tool]?" → Integration list
  └── "What's the catch with free?" → Be transparent

Write FAQ answers conversationally, not like legal text.
```

### SECTION 8: FINAL CTA
```
Lower friction version of the hero CTA.
Often softer: "Ready to stop doing X the hard way?"

Include:
  ├── Repeat primary CTA button
  ├── Trust signals (no credit card / cancel anytime / free plan)
  └── Brief re-statement of core value
```

## HEADLINE FORMULAS

```
Formula 1: Specific Outcome + Condition
  "Ship a production API in 4 hours — without the boilerplate"

Formula 2: Before/After
  "Stop managing spreadsheets. Start understanding your business."

Formula 3: Direct Question (if user's pain is strong)
  "Why does deploying take your whole Friday?"

Formula 4: Bold Claim + Qualifier
  "The fastest CI/CD pipeline. Proven with 40,000 teams."

Formula 5: Target Audience + Outcome
  "For indie developers who ship fast and sleep soundly."
```

---

## CTA LANGUAGE RULES

```
Pattern: [Action verb] + [Specificity] + [Risk reducer]

Examples:
  "Start Free — No Card Required"
  "Get Instant Access"
  "Try Free for 14 Days"
  "See It In Action (2-min demo)"
  "Create Your Free Account"
  "Book a 15-Minute Demo"
  "Download Free Template"
  "Start Your First Build"

❌ NEVER: "Get Started", "Learn More", "Click Here", "Submit", "Send"
```

## TONE OF VOICE SYSTEM

```
Before writing any copy, define 3 brand voice adjectives.
Then apply them consistently across ALL pages.

Example voice profiles:

BOLD & DIRECT:
  → Short sentences. Active voice. No fluff. Lead with facts.
  → "We built this because X was broken. We fixed it."

WARM & ENCOURAGING:
  → Conversational. Contractions ("you're", "we're"). Second person always.
  → "We know how hard it is. We've been there. Let's fix it together."

PREMIUM & AUTHORITATIVE:
  → Measured confidence. Data-backed claims. Never boastful.
  → "Trusted by engineering teams at 500+ Fortune 1000 companies."

PLAYFUL & IRREVERENT:
  → Humor is allowed. Unexpected analogies. References.
  → "Your deploy pipeline is slower than dial-up. We fixed that."

RULE: Choose ONE voice. Enforce it across EVERY page, EVERY button, EVERY email.
      Mixed voice = confused brand = low trust.
```

## AI COPY ANTI-PATTERNS (AUTO-REPLACE)

```
FIND → REPLACE:

"Empower your workflow"     → Describe what it actually does
"Seamless integration"      → Name the specific tools and how it connects
"Next-generation"           → Remove it. It means nothing.
"Cutting-edge"              → Remove it. Use the actual technology name.
"Robust solution"           → Remove it. Say what it solves.
"Industry-leading"          → Add proof or remove it.
"Unlock your potential"     → Say the specific outcome.
"Leverage our platform"     → Use our [product name] to...
"Streamline your process"   → Say which process and by how much.
"Get started today"         → [Specific action] — takes [X] minutes
"World-class"               → Add proof (awards, metrics) or remove.
"Innovative"                → Describe the innovation specifically.
"Scalable"                  → Say how large (handles 1M req/min).
"User-friendly"             → Show don't tell (screenshot, demo).
```

## SEO-OPTIMIZED COPY RULES

```
✅ Include primary keyword in H1 (naturally, not forced)
✅ Use secondary keywords in H2 subheadings
✅ First paragraph contains primary keyword
✅ Meta description: 150-160 chars, includes keyword + CTA
✅ Image alt text: descriptive, includes relevant keyword
✅ URL slugs: /feature-name (not /p?id=123)
✅ Internal links to related pages with descriptive anchor text

Meta description formula:
  [Benefit] + [How] + [CTA]
  "Ship production APIs in 4 hours with [Product]. No boilerplate required. Start free today."
```

## SCANNABILITY RULES

```
Users read 20% of text on a webpage. Design for scanning:

✅ Headlines every 2-3 paragraphs
✅ Bold key phrases within paragraphs
✅ Bullet points for lists of 3+ items
✅ Short paragraphs: max 3 sentences each
✅ Numbers and data stand out ("4 hours" not "a few hours")
✅ White space between sections (breathing room)
✅ Pull quotes for key testimonials
✅ Progress indicators for long-form content

❌ Walls of text with no visual breaks
❌ Paragraphs longer than 4 lines on mobile
❌ Important information buried at the bottom
❌ Multiple competing CTAs fighting for attention
```
